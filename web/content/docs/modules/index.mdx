Modules in ds-start are **functional blocks**: end-to-end capabilities (UI + server + env/schema + conventions) that compose with the foundation. They build on libraries like shadcn/ui and Better Auth — they are not raw component packs.

See [Philosophy](/docs/philosophy) for the block bar, preset model, and what “done” means for new modules. Reference pattern: [forms](/docs/modules/forms) and [email](/docs/modules/email).

## Available Modules

### Data & Auth

| Module | Description | Prerequisites |
|--------|-------------|---------------|
| [Prisma](/docs/modules/prisma) | Prisma 6 ORM with PostgreSQL | None |
| [Drizzle](/docs/modules/drizzle) | Drizzle ORM with PostgreSQL | None (mutually exclusive with Prisma) |
| [Better Auth](/docs/modules/auth) | Email/password + OAuth authentication | Prisma or Drizzle |
| [Clerk](/docs/modules/clerk) | Managed authentication with pre-built UI | None |
| [Stripe](/docs/modules/stripe) | Subscription billing and payments | Auth or Clerk |

### Features

| Module | Description | Prerequisites |
|--------|-------------|---------------|
| [Email](/docs/modules/email) | Transactional email with Resend | None |
| [File Uploads](/docs/modules/file-uploads) | S3-compatible file uploads | None |
| [Zustand](/docs/modules/zustand) | Client state management | None |
| [Forms](/docs/modules/forms) | JSON-driven form renderer | None |

### DevOps

| Module | Description | Prerequisites |
|--------|-------------|---------------|

## Adding Modules

Select modules through the interactive wizard when running `npx ds-start init`, or specify them with flags:

```bash
npx ds-start init my-app --prisma --auth --stripe
```

Use `--base` to scaffold the foundation without any modules, then add them later:

```bash
npx ds-start add email
npx ds-start add forms
```

Presets are curated, verified combinations of blocks. Prefer presets when you want a known-good starting set; use `add` when composing onto an existing app.
